# 1. 特殊控制符排在普通合并词表之后
SPECIAL_TOKENS = [
    "<|pad|>", "<|bos|>", "<|eos|>",
    "<|im_start|>", "<|im_end|>",
    "<|tool_call|>", "<|/tool_call|>", "<think>", "</think>"
]

def encode_ordinary(self, text: str) -> list[int]:
    ids = list(text.encode("utf-8"))  # 任何字符先拆成 0..255 字节
    while len(ids) >= 2:
        stats = _get_stats([ids])
        # 找训练时学到的合并优先级最高(ID最小)的相邻对
        pair = min(stats, key=lambda p: self.merges.get(p, float("inf")))
        if pair not in self.merges: break
        ids = _merge(ids, pair, self.merges[pair])
    return ids

def encode(self, text: str, allow_special: bool = False):
    if not allow_special:
        # 用户输入与工具返回永远走这里：文本里的 <|im_start|> 只会被当普通字母切碎！
        return self.encode_ordinary(text)

          为什么 Agent 研发特别关心 Prefix Cache？

          因为每次调工具，System Prompt 和工具列表都在最前面且不变。推理引擎把前面算好的 cache.k, cache.v 缓存下来，下轮请求直接复用，省掉重复 Prefill 算力！

五大后训练手段各自干嘛？

        
    
          
  • 黑盒数据蒸馏（src/fetch_hf.py）：用更强老师模型（如 DeepSeek-R1）生成带 <think> 的标准轨迹喂给 SFT，最快速提分。
    • 
          
  • LoRA + Merge（src/lora.py）：冻结基座，仅训旁路低秩矩阵 B@A（约 2.2% 参数）；B 全零初始化保证初始零扰动，训完可无损合回原矩阵。
    • 
          
  • DPO（src/dpo.py）：拿成对 (chosen, rejected) 数据对比冻结参考模型，直接拉高好回答相对概率。
    • 
          
  • MOPD（src/distill.py）：学生自己生成回答，按题型领域找数学/问答专家老师算全词表反向 KL，避免暴露偏差。
    • 
          
  • Dr. GRPO（src/rl_grpo.py）：同一题采 G 条轨迹，用 r - mean(r) 当优势（去掉 std 缩放与长度偏置），对的动作整条链被强化。

今晚亲手跑模型踩出的 6 个真实大坑（团队分享最抓人部分）

      

        坑 1：60 步模型不会停下来，一直往后续写

        原因：还没学会在结尾吐出 <|im_end|>。SFT 的 Loss Mask 必须把回复结尾的 <|im_end|> 设为 1，否则模型不知道何时停止。
      

      

        坑 2：GRPO 准确率卡在 0% 或 28% 纹丝不动

        原因：① 第一轮工具调用约 50 tokens，设 max_new=48 直接截断；② 若 SFT 还没训出正例或已过拟合到 100%，组内奖励全相同，Advantage 全是 0，梯度消失。
      

      

        坑 3：多轮对话第 1 轮正常、第 2 轮跑偏、第 4 轮卡住

        原因：① SFT 初期只有单轮 QA，模型没见过 user1→asst1→user2 结构（补入 500 条多轮后连续 3 轮全对）；② 累积到第 4 轮撞到 max_seq_len=512 上限触发安全截断。
      

      

        坑 4：没传 System Prompt 时，计算题反而回答了自我介绍

        原因：训练数据早期把“无 system=问答、有 system=调工具”拆开了，模型按有无 system 路由分支。统一所有数据的 SYSTEM_PROMPT 后，模型在一个框里就能自主决策。
      

      

        坑 5：问 1 * 0 时模型自己改写成了 13 * 0，工具返回 0 却答成 003

        原因：初版训练集乘法只造了 11..49 两位数，工具结果全是 3~4 位数。小模型遇到没见过的个位数和 0（OOD 分布偏移），连“抄数字”都会强行凑成两位数和三位数（后续已把 data_gen.py 扩展到覆盖 0..49 边界）。
      

      

        坑 6：保存纯 LoRA 权重时因父目录不存在报错

        原因：torch.save 不会自动建父目录。在 save_lora_only 加上 path.parent.mkdir(parents=True, exist_ok=True) 解决。
